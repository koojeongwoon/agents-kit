# 자산 탭 검색 상태 초기화 설계

## 배경

`ResourceWorkspace`는 MCP, Skill, Agent, Harness 화면에서 같은 React 컴포넌트 인스턴스를 재사용한다. 검색어는 컴포넌트 내부 `query` 상태에 저장되므로 MCP에서 검색한 뒤 Skill 탭으로 이동해도 이전 검색어가 남는다.

이 때문에 실제 Skill이 존재하더라도 목록이 숨겨지고, 현재 빈 상태 문구인 “이 Kit에 등록된 Skill이 없습니다.”가 표시되어 등록 상태를 잘못 이해하게 만든다.

## 결정

`ResourceWorkspace`가 받는 `view`가 변경되면 검색어를 빈 문자열로 초기화한다. 새 탭이 화면에 그려지기 전에 초기화하고, 화면 전체를 강제로 다시 생성하거나 탭별 검색어를 별도로 저장하지 않는다.

이 방식은 다음 특성을 가진다.

- 탭을 바꾸면 새 자산 유형의 전체 목록이 즉시 보인다.
- 선택한 Kit 범위와 배포 환경 등 상위 화면 상태는 유지된다.
- 검색어 이외의 향후 컴포넌트 상태를 불필요하게 제거하지 않는다.
- 백엔드, 로컬 탐지, 배포 계획·적용·롤백 로직은 변경하지 않는다.

## 빈 상태 문구

검색어가 없는 상태에서 자산이 0개이면 기존 자산별 문구를 유지한다.

- MCP: `이 Kit에 등록된 MCP 서버가 없습니다.`
- Skill: `이 Kit에 등록된 Skill이 없습니다.`
- Agent: `이 Kit에 등록된 Agent가 없습니다.`
- Harness: `이 Kit에 등록된 Harness가 없습니다.`

검색어가 있고 필터 결과만 0개이면 등록 상태와 구분해 `검색 결과가 없습니다.`를 표시한다. 안내 문구는 검색어를 바꾸거나 지우도록 설명한다.

## 테스트

컴포넌트를 MCP 화면으로 렌더링하고 검색어를 입력한 뒤 동일 인스턴스를 Skill 화면으로 다시 렌더링한다. Skill 검색창이 비어 있고 Skill 목록이 다시 나타나는지 검증한다.

별도 테스트에서 일치하지 않는 검색어를 입력했을 때 `검색 결과가 없습니다.`가 표시되고, 자산 미등록 문구가 표시되지 않는지 검증한다.

구현 후 GUI 전체 테스트, 타입 검사, 프로덕션 번들을 실행한다. 마지막으로 Chrome에서 MCP 검색 후 Skill 탭으로 이동해 검색어가 초기화되고 Skill 전체 목록이 보이는지 확인한다.
