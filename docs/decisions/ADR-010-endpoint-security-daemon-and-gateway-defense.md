# ADR-010: Endpoint Security Daemon and Tool Gateway Dual-Defense Architecture

> 2026-09-25 기기 신원 연동 합의: IAM이 등록·회수를 소유하고 각 서비스는 필요한 기기 신원을 OAuth/OIDC scope·claim 및 요청 증명 계약으로 소비한다. Gateway가 첫 소비자이며 다른 IAM 서비스에는 일괄 강제하지 않는다. [상세 계약](../architecture/iam-device-identity-contract.md)과 현재 구현 계획의 LM2/G-1A/G-2를 따른다.

> 현재 검토 범위는 [세 구성 요소 구현 계획](../product/three-component-implementation-plan.md)으로 구체화했다.
> Agent Kit·데몬·Tools Gateway를 구현하며 외부 네트워크 보안 제품은 필수 의존성에서 제외한다.
> 이 문서의 초기 기능 목록 전체를 이번 출시 범위로 해석하지 않는다.
> 현재 원격 MCP 경로는 AI 클라이언트→Gateway 직접 호출이다. 기기 등록·회수의 기준은 IAM, 데몬→Gateway는 정책 상태·로컬 이벤트 채널이다. 아래 인라인 데몬 경유 제안은 채택된 호출 경로가 아니다.

> 이 ADR은 초기 제안이다. 채택 범위와 구현 순서는
> [제품 계획 평가](../product/security-companion-plan.md)의 단계별 검증 결과로 결정한다.
> 아래 Decision과 Positive의 보안·성능 표현은 검증된 제품 보장이 아니다.

## Context

대상 단말은 회사 지급 PC와 업무에 사용하는 개인 소유 PC 모두다. 업무 사용 시 Agent Kit 설치·조직 등록을 필수로 하며, 관리 정책이 검증된 기기만 보호 대상 회사 자원에 접근하도록 설계한다. 회사 자료를 읽거나 외부로 전송하는 비인가 로컬/원격 MCP 사용 제한을 핵심 요구로 둔다. 이를 위해 필요한 클라이언트 관리 기능, 단말 관리 권한과 OS 통제는 단계 0에서 확인하며 비인가 MCP 차단과 기기 접근 조건을 P0에서 검증한다. 설치·heartbeat만으로 기기 무결성을 보장하지 않는다.

기업 고객들은 Claude Code, Cursor, Codex, Antigravity 등 다양한 LLM 클라이언트를 로컬 PC에서 사용하면서, 서버 측에서는 사내 자원과 API를 통제하기 위해 **Tool Gateway**를 운영하고 있다.

그러나 다음과 같은 엔터프라이즈 보안 공백이 발생한다:
1. **로컬 섀도우 도구(Shadow Tools)**: 개발자가 로컬 설정 파일(`~/.claude.json`, `.cursor/mcp.json` 등)에 검증되지 않은 오픈소스 MCP를 임의 등록하여 실행하는 행위를 중앙에서 막기 어려움.
2. **데이터 유출(DLP) 위험**: 로컬 소스코드, 환경변수(`.env`), 사내 시크릿 및 개인정보(PII)가 여과 없이 외부 LLM 또는 도구 입력으로 전달될 위험.
3. **감사 추적 부재**: 개발자 로컬 PC에서 에이전트가 어떤 파일과 명령어를 조작했는지 중앙 보안 SIEM에서 가시성을 확보하지 못함.
4. **사용자 편의성 저하**: 무조건적인 로컬 제한은 개발자 생산성을 떨어뜨려 보안 우회 시도를 유발함.

## Decision

Agent Kit을 **개발자 대면 데스크톱 앱(Control Center GUI)**과 **OS 백그라운드 보안 데몬(`agentkitd`)**, 그리고 **서버 측 Tool Gateway**가 맞물리는 **2단계 심층 방어(Dual-Defense)** 체계로 확장한다.

1. **데스크톱 앱 편의성 계층 유지 및 강화**:
   - 단일 UI에서 프롬프트/지침(AGENTS.md, rules) 및 사내 공통 자원(MCP, Skill, Subagent)을 시각적으로 작성하고 각 클라이언트로 비파괴 배포(Structured Merge).
   - 도구 차단 시 즉각 예외 결재를 올릴 수 있는 **1-Click 승인 요청 UI** 제공.
2. **로컬 백그라운드 보안 데몬(`agentkitd`) 탑재**:
   - OS 서비스 상주(`launchd`/`systemd`/WinService).
   - **Config Sentinel**: 클라이언트 설정 파일 무단 변조 실시간 감시 및 롤백.
   - **Tool Allowlist**: 중앙 전자서명 및 해시 검증을 통과한 도구만 실행(Fail-Closed).
   - **1차 인라인 DLP**: 로컬 인수 및 도구 출력 대상 정규식/NER 기반 실시간 시크릿/PII 마스킹.
   - **로컬 감사 버퍼**: SQLite WAL 기반 해시체인 로그 적재 후 중앙 스트리밍.
   - **브라우저 제어 가드**: 격리 Chromium 프로필 구동 및 사내 도메인 화이트리스트 강제.
3. **서버 측 Tool Gateway 2차 심층 방어**:
   - **이상 탐지 & 서킷 브레이커**: 에이전트 호출 폭주 및 대량 데이터 덤프 감지 시 실시간 세션 동결.
   - **2차 정밀 DLP & 프롬프트 인젝션 방어**: 문맥 기반 사내 특화 기밀 및 탈옥 방어.
   - **원격 킬 스위치 (Instant Kill-Switch)**: 단말 분실 또는 이상 징후 시 전사/엔드포인트별 권한 즉각 회수.
   - **불변 감사 저장소 (WORM)**: 로컬 해시체인 로그와 게이트웨이 도구 로그 결합 보관 (SIEM 연동).
4. **모바일 기기의 원격 컨트롤러 및 생체인증 2FA 포지셔닝**:
   - 모바일 기기 자체를 무겁게 감시·통제(MDM 침해/BYOD 갈등)하는 대신, **"모바일 기기로 안전하게 기존 PC/서버 업무 환경을 통제하는 원격 리모컨 & 생체인증(FaceID/지문) 2FA 결재 도장"** 모델로 정의.
   - 고위험 액션의 모바일 푸시 2단계 승인, 외근/이동 중 안전한 작업 위임 프록시, 비상 킬스위치 트리거 제공.

## Status

Proposed — 기능별 실현 가능성 및 단계 0 검증 전. Accepted로 전환하지 않음.

## Consequences

### Positive
- 개발자에게는 도구 및 프롬프트 관리의 극상의 편의성을 유지하면서, 보안팀에는 엔드포인트와 서버를 아우르는 무결점 거버넌스를 제공.
- 로컬 PC가 탈취되거나 로컬 데몬이 우회되더라도 서버 측 Gateway에서 2차 차단(서킷 브레이커/토큰 취소)이 가능.
- 클라이언트별 최신 규격(Claude Code의 `AGENTS.md` 지원 등)에 맞춘 유연한 배포 지원.

### Negative / Trade-offs
- 로컬 OS 서비스 데몬(`agentkitd`) 설치 및 관리(MDM 패키징) 오버헤드 발생.
- 양방향 인라인 DLP 파이프라인으로 인한 수 밀리초(ms) 단위의 도구 호출 지연 시간 추가 (고속 매칭 엔진 적용으로 최소화 필요).
